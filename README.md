# GRAFF — Fast & Delicious · мобильное приложение

Приложение кафе быстрого питания **GRAFF** («Граф»), Чири-Юрт: меню в стиле печатного листа, заказ с телефона,
выбор столика в зале и на террасе, статус готовности с таймером-кольцом и push-баннером, профиль, «О нас»
и мини-панель персонала (кухня). Язык интерфейса — русский, тема только светлая, портретный мобильный экран.

**Открыть приложение: https://zhamulaevraiza-debug.github.io/graff-app/**
Ссылка работает на телефоне: откройте её в браузере и добавьте на главный экран, приложение запустится
в полноэкранном режиме и будет работать без сети.

Реализация прототипа из Claude Design: исходники прототипа лежат в [`design/`](design/)
(`GRAFF App.dc.html` — сам прототип, `BRIEF.md` — бриф с палитрой, типографикой, меню и экранами).

## Стек и запуск

Vite + React 19 + TypeScript + zustand. PWA: ставится на домашний экран iOS/Android из браузера
(`manifest.webmanifest`, портретная ориентация, safe-area). Для магазинов приложений код оборачивается в Capacitor без изменений.

```bash
npm install
npm run dev        # http://localhost:5173  (флаг --host: открыть с телефона в той же сети)
npm run build      # проверка типов + сборка в dist/
npm run preview    # просмотр сборки
npm run typecheck  # только проверка типов
```

## Публикация (продакшен)

Сейчас приложение опубликовано на GitHub Pages: каждый push в `main` пересобирает его и выкладывает
по адресу https://zhamulaevraiza-debug.github.io/graff-app/ (workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)).
Базовый путь подставляется переменной `VITE_BASE`, поэтому та же сборка работает и в подпапке, и в корне домена.

### Свой домен

Приложение — статические файлы, серверная часть не нужна. Собранная папка `dist/` кладётся в корень домена.

```bash
npm ci && npm run build
```

Для подпапки соберите с базовым путём: `VITE_BASE=/graff-app/ npm run build`.

Требования к хостингу:

- **HTTPS обязателен** — иначе не работают установка на домашний экран, service worker и уведомления.
- Приложение должно лежать **в корне домена** (`https://пример.рф/`), потому что манифест, иконки и `sw.js` берутся по абсолютным путям.
- Все неизвестные пути отдавать `index.html` (одностраничное приложение). Пример для nginx:

```nginx
server {
  listen 443 ssl http2;
  server_name graff.example.ru;
  root /var/www/graff/dist;

  location / { try_files $uri $uri/ /index.html; }
  location = /sw.js { add_header Cache-Control "no-cache"; }
  location /assets/ { expires 1y; add_header Cache-Control "public, immutable"; }
}
```

Подойдёт и любой статический хостинг (Netlify, Vercel, Cloudflare Pages, объектное хранилище Yandex Cloud/VK Cloud) с теми же правилами. Сборка и проверка типов на каждый push настроены в [`.github/workflows/ci.yml`](.github/workflows/ci.yml).

Как установить на телефон: открыть адрес в браузере, затем «Добавить на главный экран» (Android, меню браузера)
или «Поделиться» → «На экран „Домой“» (iPhone, Safari). Приложение откроется в полноэкранном режиме,
а меню и заказы будут доступны без сети (service worker [`public/sw.js`](public/sw.js)).

Свой домен подключается в настройках репозитория, раздел Pages, поле Custom domain.

## Два режима работы

Приложение собирается в одном из двух режимов, режим задаётся переменной `VITE_API_URL` при сборке.

| | Демонстрация (`VITE_API_URL` пуст) | Боевой режим (`VITE_API_URL` задан) |
|---|---|---|
| Заказы | живут в памяти устройства | уходят на сервер кафе, кухня видит их сразу |
| Вход | любой код из 4 цифр | настоящий код в SMS от оператора связи |
| Статусы | персонал ставит в панели, всё живёт на устройстве | персонал ставит в панели, клиент видит их в реальном времени с сервера |
| Панель персонала | открыта из профиля | вход по логину и PIN сотрудника |
| Столики | локальные | общие для всех устройств |
| Уведомления | баннер внутри приложения | баннер плюс push на телефон, даже когда приложение закрыто |

Демонстрация нужна, чтобы показать приложение без сервера: она развёрнута на GitHub Pages.
Для работы кафе нужен боевой режим, он описан ниже и в [`server/README.md`](server/README.md).

## Сервер

Серверная часть лежит в папке [`server/`](server/): Node 22, Fastify, SQLite. Она принимает заказы,
отправляет коды входа через SMS, ведёт статусы и раздаёт живые обновления через поток событий.
Персональные данные (телефон, имя, история заказов) хранятся только в её базе, поэтому сервер
размещается в России (152-ФЗ, часть 5 статьи 18).

```bash
cd server && npm install && npm run dev
```

Проверки сервера (сервер должен быть запущен с `SMS_PROVIDER=log`):

| Команда | Что проверяет |
|---|---|
| `npm run test:smoke` | вход по коду, заказ, работа кухни, выгрузка и удаление данных |
| `npm run test:stream` | живые обновления: клиент видит свой заказ, кухня — все, чужие не приходят |
| `npm run test:security` | чужие заказы, подделка токена, перебор кода и PIN, сумма заказа считается сервером |

Те же проверки выполняются автоматически при каждом изменении кода (GitHub Actions).

Полное развёртывание одной командой на сервере, вместе с nginx и сертификатом:

```bash
docker compose up -d --build
```

### Что нужно, чтобы включить боевой режим

1. **Сервер в России** — виртуальная машина у российского провайдера (Yandex Cloud, VK Cloud, Selectel, Timeweb):
   там будут храниться персональные данные гостей, этого требует 152-ФЗ.
2. **Домен и сертификат** — без HTTPS не работают установка на телефон, уведомления и вход.
3. **Договор с оператором SMS** — sms.ru или smsc.ru, с зарегистрированным именем отправителя.
   Ключи прописываются в `server/.env`, до этого сервер работает в режиме `SMS_PROVIDER=log` (код пишется в журнал).
4. **Ключи для push** — генерируются одной командой `npm run vapid` в папке `server` и вписываются в `server/.env`.
5. **Учётные записи кухни** — `npm run seed:staff -- kitchen 1234 Кухня` (PIN задаёт владелец, не оставляйте пример).

Пока этого нет, приложение работает как демонстрация: заказы не уходят на кухню, а живут на устройстве.

## Как устроен демонстрационный режим

Сервера пока нет, поэтому клиент и панель персонала работают с одним локальным состоянием (localStorage).
Заказы никуда не уходят и живут только на этом устройстве.

**Вымышленных заказов нет.** Приложение начинает с чистой ленты: заказов ноль, столики свободны,
счёт начинается с номера 1001 — с того же, с которого считает сервер. Всё, что появится на кухне,
вы оформите сами.

**Статусы ведёт персонал, а не таймер.** Гость оформляет заказ — он встаёт в очередь со словами
«Ждём кухню». Дальше кто-то должен открыть панель и нажать «Принять», выбрав время. Так же, как
на настоящей кухне, и так же, как это будет работать с сервером. Время идёт по-настоящему:
«~15 мин» — это пятнадцать настоящих минут.

Чтобы показать обе стороны сразу, откройте панель персонала (`/#/staff` или «Профиль → Режим персонала»)
во второй вкладке того же браузера: у клиента статус, таймер и push-баннеры («Заказ принят!»,
«Ваш заказ готов!», «Время готовности изменено») обновятся сами. Между вкладками передаются только
общие данные (заказы, столики, настройки, профиль), а экран и корзина у каждой вкладки свои.

Точки подключения бэкенда: `placeOrder`, `setStatus`, `bumpEta`, `toggleOccupied`, `submitStaffForm`
в [`src/state/store.ts`](src/state/store.ts) и обработчик `storage` в [`src/App.tsx`](src/App.tsx)
(его место займёт подписка на сервер).

Адреса экранов: `#/home`, `#/menu`, `#/cart`, `#/status`, `#/profile` (`#/profile/orders`, `#/profile/favs`), `#/about`, `#/staff`, `#/splash`.

**Вход в панель кухни** закрыт в обоих режимах и идёт в два шага: код заведения (общий, цифрами),
затем номер сотрудника и его личный PIN. Панель, оставленную открытой, приложение закрывает само
через 15 минут без действий. В демонстрации коды проверяет само устройство и они показаны прямо
на экране входа (заведение 2468, сотрудник 01 с PIN 1234) — это показ порядка входа, а не защита;
на сервере код задаётся в `STAFF_PANEL_CODE`, а PIN хранятся в виде хэша.

**Настройки** (внизу панели персонала):

| Настройка | По умолчанию | Смысл |
|---|---|---|
| Push-баннеры | вкл | баннер «как уведомление» сверху экрана; при свёрнутом приложении и выданном разрешении — системное уведомление |
| Фото на главной | вкл | крупный снимок рядом с заголовком; выключите, пока нет своей фотографии |
| Заголовки экранов | плашка | плашка (иконка + ЗАГЛАВНЫЕ) или рукописный медный текст с короной |
