# GRAFF — Fast & Delicious · мобильное приложение

Приложение кафе быстрого питания **GRAFF** («Граф»), Чири-Юрт: меню в стиле печатного листа, заказ с телефона,
выбор столика в зале и на террасе, статус готовности с таймером-кольцом и push-баннером, профиль, «О нас»
и мини-панель персонала (кухня). Язык интерфейса — русский, тема только светлая, портретный мобильный экран.

Реализация прототипа из Claude Design: исходники прототипа лежат в [`design/`](design/)
(`GRAFF App.dc.html` — сам прототип, `BRIEF.md` — бриф с палитрой, типографикой, меню и экранами).

## Стек и запуск

Vite + React 19 + TypeScript + zustand. PWA: ставится на домашний экран iOS/Android из браузера
(`manifest.webmanifest`, портретная ориентация, safe-area). Для магазинов приложений код оборачивается в Capacitor без изменений.

```bash
npm install
npm run dev        # http://localhost:5173  (флаг --host: открыть с телефона в той же сети)
npm run build      # проверка типов + сборка в dist/
npm run preview    # просмотр сборки
npm run typecheck  # только проверка типов
```

## Публикация (продакшен)

Приложение — статические файлы, серверная часть не нужна. Собранная папка `dist/` кладётся в корень домена.

```bash
npm ci && npm run build
```

Требования к хостингу:

- **HTTPS обязателен** — иначе не работают установка на домашний экран, service worker и уведомления.
- Приложение должно лежать **в корне домена** (`https://пример.рф/`), потому что манифест, иконки и `sw.js` берутся по абсолютным путям.
- Все неизвестные пути отдавать `index.html` (одностраничное приложение). Пример для nginx:

```nginx
server {
  listen 443 ssl http2;
  server_name graff.example.ru;
  root /var/www/graff/dist;

  location / { try_files $uri $uri/ /index.html; }
  location = /sw.js { add_header Cache-Control "no-cache"; }
  location /assets/ { expires 1y; add_header Cache-Control "public, immutable"; }
}
```

Подойдёт и любой статический хостинг (Netlify, Vercel, Cloudflare Pages, объектное хранилище Yandex Cloud/VK Cloud) с теми же правилами. Сборка и проверка типов на каждый push настроены в [`.github/workflows/ci.yml`](.github/workflows/ci.yml).

После деплоя приложение можно установить на телефон: в браузере «Добавить на главный экран». Оно откроется в полноэкранном режиме, а меню и заказы будут доступны без сети (service worker [`public/sw.js`](public/sw.js)).

## Правовая часть (Россия)

> Это не юридическая консультация. Тексты в [`src/data/legal.ts`](src/data/legal.ts) — **шаблоны**: замените всё в квадратных скобках на реальные данные и покажите документы юристу. Ответственность за содержание несёт владелец кафе.

Что уже сделано в приложении:

| Требование | Норма | Где в приложении |
|---|---|---|
| Отдельное согласие на обработку персональных данных, без него вход невозможен | 152-ФЗ, ст. 9 | чекбокс на экране входа, дата и версия согласия сохраняются |
| Отдельное, не предзаполненное согласие на рекламные SMS и push с названием кафе и каналов | ФЗ «О рекламе», ст. 18 | второй чекбокс при входе и переключатель «Акции и новинки» в профиле |
| Политика обработки персональных данных в открытом доступе | 152-ФЗ, ст. 18.1 | «Профиль» → «Правовая информация» |
| Оферта: правила заказа, оплаты, отмены, претензий | ГК РФ, ст. 435–438; ЗоЗПП | там же, документ «Пользовательское соглашение и оферта» |
| Отзыв согласия и удаление аккаунта в один шаг | 152-ФЗ, ст. 9 ч. 2; требования Google Play и App Store | «Профиль» → «Удалить аккаунт и данные» |
| Сведения об исполнителе: наименование, ИНН, ОГРН, адрес, режим работы | ЗоЗПП, ст. 9; Правила № 1515 | экран «О нас» и документ «Реквизиты» |
| Состав, масса порции, пищевая ценность, аллергены | Правила № 1515, п. 9; ЗоЗПП, ст. 10; ТР ТС 022/2011 | блок в карточке блюда (данные заполняются в `ITEM_INFO`) |
| Документ, подтверждающий предварительный заказ | Правила № 1515, п. 14 | блок «Подтверждение заказа» на экране статуса и история заказов |
| Цены в рублях, честное описание способов оплаты | ЗоЗПП, ст. 10 | меню, корзина, оферта |
| Книга отзывов и порядок претензий | Правила № 1515 | документ «Реквизиты» |

Что должен сделать владелец до запуска (вне кода):

1. **Заполнить реквизиты** в `src/data/legal.ts` (`COMPANY`) и дату редакции `LEGAL_UPDATED`; при изменении текстов поднять `LEGAL_VERSION`.
2. **Подать уведомление в Роскомнадзор** об обработке персональных данных — до начала обработки, через личный кабинет на сайте РКН. Сообщать об изменениях сведений и о прекращении обработки.
3. **Разместить базу данных в России** (152-ФЗ, ч. 5 ст. 18): сервер и хостинг — российские; это касается будущего бэкенда, SMS-шлюза и push-сервиса.
4. **Оформить внутренние документы по персональным данным**: приказ о назначении ответственного, положение об обработке, оценка вреда субъектам, определение уровня защищённости, журнал согласий и актов уничтожения данных.
5. **Заключить договоры-поручения** на обработку персональных данных с подрядчиками: SMS-шлюз, хостинг, сервис push-уведомлений.
6. **Заполнить данные о блюдах** (`ITEM_INFO`): состав, способ приготовления, масса порции, калорийность и БЖУ, аллергены. Без этого карточка блюда показывает предупреждение, что сведения уточняются.
7. **Настроить кассу**: чек выдаётся до расчёта, порядок «клиент согласился оплатить → чек → оплата» (54-ФЗ, ст. 1.2 п. 5.11).
8. **Книга отзывов и предложений** — в кафе, выдаётся по требованию.
9. **Реклама вне приложения** (Яндекс Директ, VK, блогеры) требует пометки «Реклама», указания рекламодателя и токена erid с отчётностью в ЕРИР. Собственное меню и push о статусе заказа маркировки не требуют.
10. **При публикации в сторах**: политика конфиденциальности по внешней ссылке, форма Data safety (Google Play), Privacy Labels (App Store), веб-ссылка на удаление аккаунта.
11. **Утечка данных** — уведомить Роскомнадзор в течение 24 часов, результаты расследования — в течение 72 часов.

Полный разбор требований с нормами и штрафами лежит в [`docs/legal-requirements.md`](docs/legal-requirements.md).

## Что заполнить по данным кафе

- **Адрес и часы** — константы `ADDRESS`, `HOURS`, `TOWN`, `REGION`, `MAPS_URL` в [`src/data/menu.ts`](src/data/menu.ts) (сейчас плейсхолдеры `[АДРЕС]`, `[ЧАСЫ РАБОТЫ]`).
- **Телефон** — `PHONE_DISPLAY` / `PHONE_TEL` там же (сейчас +7 938 900-90-67).
- **Столики** — `ZONES` (допущение прототипа: терраса 1–6, зал 7–14).
- **Составы и описания блюд** — словарь `DESCRIPTIONS` (ключ — id позиции, например `burgers-0-0`); пока показывается `[Состав и описание блюда]`.
- **Фото** — положите файлы в `public/photos/` с именами слотов, они подхватятся автоматически (jpg / png / webp):
  `hero-burger`, `hero-fries` (главная), `cat-burgers`, `cat-fastfood`, `cat-new`, `cat-tea`, `cat-jam`, `cat-drinks` (меню),
  `dish-<id>` (карточка блюда, id как в `menu.ts`), `new-<id>` (карусель новинок), `about-map`, `about-hall`, `about-terrace` («О нас»).
  Пока фото нет — на месте слота мягкий бежевый плейсхолдер с контурной иконкой.
- **Логотип** — монограмма «G» и словесный знак сейчас нарисованы в SVG (`src/components/Logo.tsx`, `public/icon.svg`); векторный логотип можно подставить туда же.

## Как это работает без бэкенда

Сервера пока нет, поэтому клиент и панель персонала работают с одним локальным состоянием (localStorage).
Откройте панель персонала (`/#/staff` или «Профиль → Режим персонала») во второй вкладке того же браузера —
у клиента статус, таймер и push-баннеры («Заказ принят!», «Ваш заказ готов!», «Время готовности изменено»)
обновятся сами: между вкладками передаются только общие данные (заказы, столики, настройки, профиль), а экран
и корзина у каждой вкладки свои. Точки подключения бэкенда: `placeOrder`, `setStatus`, `bumpEta`, `toggleOccupied`,
`submitStaffForm` в [`src/state/store.ts`](src/state/store.ts), `kitchenTick` в [`src/lib/orders.ts`](src/lib/orders.ts)
и обработчик `storage` в [`src/App.tsx`](src/App.tsx) (его место займёт подписка на сервер).

Адреса экранов: `#/home`, `#/menu`, `#/cart`, `#/status`, `#/profile` (`#/profile/orders`, `#/profile/favs`), `#/about`, `#/staff`, `#/splash`.

**Настройки демо** (внизу панели персонала), перенесённые из Tweaks прототипа:

| Настройка | По умолчанию | Смысл |
|---|---|---|
| Кухня-автопилот | вкл | заказы сами проходят Принят → Готовится → Готов → Выдан |
| Ускоренное время | вкл | 1 минута = 5 секунд, чтобы посмотреть статус без ожидания |
| Push-баннеры | вкл | баннер «как уведомление» сверху экрана; при свёрнутом приложении и выданном разрешении — системное уведомление |
| Заголовки экранов | плашка | плашка (иконка + ЗАГЛАВНЫЕ) или рукописный медный текст с короной |

Для реальной работы выключите автопилот и ускоренное время — тогда статусы ведёт персонал.

## Права

Код и тексты приложения принадлежат владельцу кафе GRAFF. Отдельная лицензия не предоставляется:
использование, копирование и распространение — только с разрешения владельца.

## Экраны

Сплэш / вход по номеру (SMS-код, имя, «Продолжить без входа») · Главная (шапка с кнопкой «Позвонить», hero как верх меню,
обещания бренда, «Ваш заказ», формат получения, категории, новинки ★, адрес) · Меню (табы-плашки, точечные лидеры, чипы размеров,
плавающая корзина) · Карточка блюда (порция/объём, соусы, количество) · Корзина и оформление (формат, схема столиков, время
самовывоза, имя и телефон, оплата, итог) · Статус заказа (таймер-кольцо, шаги, состав, «Позвонить», «Повторить») · Профиль
(история, избранное, любимый формат, уведомления) · О нас (карта, адрес, часы, телефон, маршрут, фото) · Персонал (заказы,
заказ по звонку, время готовности, +5 мин, столики).
